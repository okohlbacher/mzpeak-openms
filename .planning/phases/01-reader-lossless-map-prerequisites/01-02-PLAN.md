<join_model>
<!-- review H1/H2: the EXACT join contract executors must implement. -->

The output is `std::map<uint64_t, SpectrumMetadata> out`, keyed by the REAL
`spectrum.index` value (already built by the RDR-10b pass). The precursor /
selected_ion / scan columns are SIBLING top-level ChunkedArrays in the SAME table;
their chunk boundaries are NOT guaranteed to match the spectrum column's chunks,
and a facet row's chunk-local index is NOT a spectrum index.

THE JOIN KEY IS THE `source_index` VALUE, ALWAYS:
  for each facet column (precursor, selected_ion, scan):
    for each chunk (StructArray):
      for each chunk-local row r:
        si = opt_int<uint64_t>(facet_chunk, "source_index", r)   // value, not r
        if (!si) continue                       // MS1 rows: source_index NULL -> skip
        auto it = out.find(*si);
        if (it == out.end()) {                  // LOW review: no silent loss
          log a warning "facet source_index N has no matching spectrum" and continue;
        }
        // build the facet struct from chunk-local row r, store into it->second
NEVER index `out` positionally, and NEVER assume facet row r corresponds to
spectrum row r. The chunk-local r is only used to read THIS facet chunk's own
values; cross-spectrum association is exclusively via the `source_index` value.

SELECTED-ION ATTACHMENT IS BY (source_index, precursor_index), NOT back():
  Build precursors FIRST (Task 2 precursor pass), keyed within each spectrum by
  precursor_index. Then in the selected_ion pass, read both the selected_ion row's
  `source_index` (-> spectrum) AND its `precursor_index`, and attach the
  SelectedIonInfo to the PrecursorInfo in out[si].precursors whose precursor_index
  matches. If no precursor with that precursor_index exists yet (selected_ion seen
  before/without its precursor), CREATE a PrecursorInfo carrying that precursor_index
  to hold the ion (do not drop it, do not attach to an arbitrary precursor).
  This makes multiple-precursors-per-spectrum and multiple-ions-per-precursor both
  correct (DIA-safe), independent of row ordering.
</join_model>
