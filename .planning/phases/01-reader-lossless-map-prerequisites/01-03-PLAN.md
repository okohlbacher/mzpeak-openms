<objective>
Implement RDR-9b: a typed accessor exposing each spectrum's `auxiliary_arrays`
(name/CV term + data_type/compression/unit + parameters + decoded values), so
Phase 2 can map them to OpenMS `MSSpectrum::FloatDataArrays`.

`number_of_auxiliary_arrays == 0` in every bundled fixture. Honoring CONTEXT.md's
"do not write unvalidated decode paths" (the reviewers caught a conflict here), the
work is split:
  (A) IMPLEMENT + VALIDATE NOW — structural: schema parsing of every aux-array
      field, empty-list handling, and a `number_of_auxiliary_arrays ==
      auxiliary_arrays.size()` consistency assert. These ARE exercised on the
      bundled fixtures (every row's list is empty) and ship as validated.
  (B) FIXTURE-GATED FOLLOW-UP — the raw-byte float32/float64/int32 VALUE decode.
      Because no bundled fixture carries aux bytes, this path is NOT validated. It
      is shipped behind a clearly-marked "no fixture data — decode unverified" note,
      a mandatory byte-length guard, and a `values_decoded` flag so callers can tell
      decoded-empty from corrupt/undecoded. It never reinterprets a misaligned
      buffer.

Per the orchestrator's scope decision, RDR-9b does NOT block the phase.

This plan also runs the FINAL phase gate: full `meson test` + `scripts/e2e.sh`
green, and a final clang-format diff-verify across all files this phase touched.

Pure standalone mzpeak-lib work on branch `writer_test`. NO OpenMS code.

Purpose: Phase 2 FloatDataArrays mapping needs a typed aux-array accessor.
Output: AuxiliaryArray struct, the structural decode (validated), the gated/guarded
raw-byte decode, structural test, phase gate.
</objective>

rejected a misaligned buffer — Phase 2 must NOT read empty-as-decoded here.

PART A — STRUCTURAL DECODE (implemented + VALIDATED NOW). In `read_spectra_metadata`
per-row loop (the spectrum-struct pass), decode `spectrum.auxiliary_arrays`:
GetFieldByName("auxiliary_arrays") → if absent/NULL, leave empty. Cast to
`arrow::LargeListArray`; iterate `[value_offset(r), value_offset(r+1))` (same idiom
as read_cv_params_from_list); each item struct → build an AuxiliaryArray:
`name` via the plan-01 `extract_one_cv_param(name_struct, item_row)` (REUSE the
factored single-CvParam helper from plan 01 on the item's "name" struct — do NOT
re-inline the value-union decode); `data_type`/`compression`/`unit` via get_string;
`parameters` via read_cv_params_from_list(item, "parameters", k);
`data_processing_ref` via get_string. Append to `m.auxiliary_arrays`. On the
bundled fixtures every row's list is empty so the item body never runs, but the
schema field access + empty-list path IS exercised and validated.

COUNT-CONSISTENCY ASSERT (Codex review): read `number_of_auxiliary_arrays` (uint32)
via opt_int<uint64_t> and assert `number_of_auxiliary_arrays ==
m.auxiliary_arrays.size()` (treat absent count as 0). On mismatch throw a
ParquetError (the file's self-declared count disagrees with the materialized list —
a corruption signal). This guards the structural round-trip.

PART B — RAW-BYTE VALUE DECODE (FIXTURE-GATED FOLLOW-UP; NOT validated). Implement
the `values` decode as a clearly-marked, guarded path that sets `values_decoded`:
read the `data` large_list<uint8> for the item; if it has zero bytes →
`values.clear(); values_decoded = true;` (a legitimately empty decoded array). If it
has bytes, switch on the lowercase `data_type` ("float32"/"int32" → element size 4;
"float64" → element size 8; default → leave values empty, values_decoded=false,
comment "unknown data_type — decode deferred"). BYTE-LENGTH GUARD (mandatory):
before reinterpreting, require `data.size() % element_size == 0`; on mismatch leave
`values` empty, set `values_decoded=false`, and do NOT reinterpret the bytes (a
truncated/misaligned buffer must never be reinterpreted). Only when the guard
passes, convert each element to float and set `values_decoded=true`. Wrap this whole
Part-B block in a clearly-marked comment: "FIXTURE-GATED FOLLOW-UP — no bundled
fixture carries aux bytes (number_of_auxiliary_arrays==0 everywhere), so this VALUE
decode is UNVERIFIED against ground truth; it is byte-length-guarded and flagged via
values_decoded; value-level correctness awaits a fixture with populated aux data
(honors CONTEXT.md 'do not ship unvalidated decode paths' — this path is gated, not
asserted as validated)."

Treat data_type as opaque (Pitfall 5): do NOT route through the PSI::DataType enum.

PART C — TEST (structural, validated). Extend `test/spectrum_metadata_test.cpp`: for
every spectrum in small.mzpeak (and one check on has_uv.mzpeak), assert
`auxiliary_arrays` is empty, reading it does not throw/crash, and (the count assert)
the reader did not throw on `number_of_auxiliary_arrays == size()`. Document in a
test comment that VALUE-level aux assertions are deferred pending a populated
fixture, and that `values_decoded` is the decoded-vs-undecoded discriminator.
